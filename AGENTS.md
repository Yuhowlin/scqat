# AGENTS.md — scqat

**You are reading the contributor brief.** If you are working in the maintainer's lab
tree, read [CLAUDE.md](CLAUDE.md) instead — it is the fuller architecture document, and
its workflow rules assume a shared, live checkout.

## What this repo is

scqat is the **analysis half** of the scqo stack: one estimator per experiment, plus the
shared fitters and tools they use. It is a plain pip-installable library — it must stay
importable on its own, with no side effects at import time.

It is the **base of the import arrow**. [SCQO](https://github.com/shiau109/SCQO) consumes
scqat (lazy-imported from `estimate()`); scqat consumes nothing from SCQO. A change here
can silently break every experiment downstream, which is why SCQO pins a version floor
against it in `RELEASES.toml`.

## The rules that matter most

**1. The import arrow points one way.** `workflows → estimators → tools`, and
`parsers → nothing`. In particular `tools` must NOT import from `estimators`, `parsers`
or `workflows` — that is what lets an external simulation repo reuse `tools` without
dragging experiment logic in.

**2. Estimators never call estimators.** When an analysis needs another experiment's fit
as an inner step, the shared piece is a *pure per-trace reduction* living in `tools/`.
`tests/test_no_estimator_layering.py` is the static capstone.

**3. Every estimator is a subpackage**, never a flat module:

```
estimators/<name>/
    __init__.py      # re-exports the estimator class
    estimator.py     # the BaseEstimator subclass
    visualization.py # plotting helpers (consume plot_data)
```

**4. The output contract.** `extract_parameters()` does the heavy work **once**;
`extract_metadata()` and `build_plot_data()` are pure projections of it.
`generate_figures()` must draw from **`plot_data` alone** — if a figure can be redrawn
from plot data, so can an external consumer.

**5. Raw data must always be plottable.** A run whose fit failed must still produce its
raw-data figure. `build_plot_data` never raises on a failed fit (fit fields degrade to
NaN, never absent), and `generate_figures` returns `render_figures({...}, label=...)` so
one figure's failure cannot drop another. SCQO's artifact fallback drops **all** figures
on any single plotter exception — that is how a real run once lost its raw spectrogram.

`CLAUDE.md` has the full text of each, plus the multi-method estimator pattern.

## Setup

scqat must sit **as a sibling** of SCQO under one parent, under its own name — SCQO
resolves it as `{ path = "../scqat" }`:

```bash
cd <parent>
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -e ./scqat -e "./SCQO[viewer]" pytest
```

Windows: `.venv\Scripts\python.exe`.

## Testing

```bash
uv run --extra dev pytest tests/test_<name>_estimator.py -q
```

**`--extra dev` is required** — pytest is an optional extra, so bare `uv run pytest`
dies with `Failed to spawn: pytest`. Tests are named after what they test, so select by
**file name**, not `-k`.

Blast radius follows the import arrow: an estimator edit is local; a `tools/` edit
reaches **every consuming family** — the generated table in `CLAUDE.md` lists them, and
`tests/test_docs_current.py` keeps it honest. Run the full suite for a shared-core edit
(`core/base_estimator.py`, `tools/function_fitting.py`, `estimators/__init__.py`).

**Always report the exact command you ran.** Some estimators have no test at all — the
generated coverage-gap list in `CLAUDE.md` names them. If your edit is in one of those,
say so plainly rather than reporting a targeted run as though it proved something.

## Branch and PR

1. `feature/<slug>`, never `main`.
2. **Same branch name in every repo you touch** — SCQO's CI uses it to pair your SCQO
   branch with your scqat branch.
3. scqat merges **first** (`scqat → SCQO → drivers`). If your change adds something SCQO
   will lazy-import, say so in the PR: that becomes a version floor in `RELEASES.toml`,
   and getting it wrong is a silent failure downstream.

Full detail: [SCQO's CONTRIBUTING.md](https://github.com/shiau109/SCQO/blob/main/CONTRIBUTING.md).

## Do not

- Do not put file I/O in `estimators/` or physics in `parsers/`.
- Do not use `pickle` for artifacts — metadata is JSON, plot data is netCDF, both
  self-describing so a non-Python consumer can reload them.
- Do not put external or absolute data paths in `tests/`. Tests use synthetic data or a
  small committed fixture.
- Do not hand-maintain a list that can be derived — two blocks in `CLAUDE.md` are
  generated by `scripts/update_docs.py` because the hand-kept versions rotted badly.
- Do not add a new fitter without registering it (`@register_fitter('<name>')`) and
  writing its `tests/` file; an unregistered fitter fails at `get_fitter()`, not at import.
